## 1. أبرز التحديثات في الإصدار الأخير (v2.1.0)

1. **إسناد محرك القواعد إلى نموذج القرارات `typesafe/jev-1.13` عبر OpenRouter:**
   - في الوضع الحي، يتولى نموذج القرارات المتخصص **`typesafe/jev-1.13`** فحص شروط العقد، التحقق الحتمي من رقم العضوية التأمينية، ورصد تعارض التوثيق السريري وتوجيه مسار المعاملة عبر واجهة `https://openrouter.ai/api/alpha/decisions` بسرعة فائقة بالمللي ثانية (~200–350 ms).
   - في الوضع الثابت (المحاكاة المحلية)، يتولى محرك TypeScript البديل تنفيذ القواعد نفسها محلياً وبشكل حتمي دون الحاجة لأي اتصال بالشبكة.

2. **العزل التام لخدمات Google في الوضع الحي (Zero Google API Usage):**
   - تم قفل وتعطيل أي استدعاء لنماذج أو خدمات Google/Gemini في الوضع الحي، لضمان مشاركة رابط التطبيق العام بأمان دون استهلاك أي رصيد أو كوتا من حساب Google الخاص بك.
   - يعتمد التطبيق في الوضع الحي بنسبة **100% على رصيد OpenRouter**:
     - **محرك القواعد والقرارات:** `typesafe/jev-1.13` (OpenRouter Decisions).
     - **الاستدلال السريري واستخراج الأدلة:** `qwen/qwen-2.5-72b-instruct` (OpenRouter Chat).
     - **التصنيف الموازي في الظل:** `qwen/qwen-2.5-72b-instruct` (OpenRouter Chat).

3. **التعرف التلقائي والمرن على مفاتيح البيئة:**
   - قراءة ديناميكية للمتغيرات البيئية تدعم كلاً من `OPENROUTER_API_KEY` و `OPENROUTER_API_KE` كإجراء احترازي لضمان استقرار العمل عند إدخال المفاتيح عبر واجهات الإدارة المختلفة.

## 2. ملخص المعمارية الفنية (Technical Stack Overview)

| الطبقة / المكون | التقنية المعتمدة | التفاصيل والوظيفة |
|---|---|---|
| **بيئة التشغيل واللغة** | Node.js + TypeScript 7.x (ES2022) | تجميع صارم (Strict Typing) للنماذج والموارد والعقود |
| **إطار عمل الواجهة** | React 19.0.1 + Vite 8.3 | واجهة تفاعلية كاملة تدعم الاتجاه العربي RTL وخط Cairo |
| **تنسيق وتصميم الواجهة** | Tailwind CSS v4.3.3 + Motion | مظهر عصري، تباين لوني مدروس، مع عزل ثنائي الاتجاه (Bidi Isolation) |
| **المستودع السريري (FHIR)** | `@medplum/mock` + `@medplum/core` | استخدام فعلي لـ `MockClient` و`MemoryRepository` لإدارة الموارد السريرية |
| **خادم التطبيق والوسيط الآمن** | Express 4.21.2 + Vite Middleware | معمارية Full-Stack عبر `server.ts` تحمي الأسرار وتمنع كشف المفاتيح في المتصفح |
| **محرك القواعد والقرارات** | `typesafe/jev-1.13` (حي) + TypeScript (ثابت) | فحص الشروط، والتحقق الحتمي، وتوجيه المسارات بالمللي ثانية |
| **بوابة الذكاء الاصطناعي** | Dual-Mode AI Gateway (OpenRouter حصرياً) | استدلال سريري وتظليل أدلة حرفية عبر Qwen 2.5 72B دون لمس كوتا Google |
| **الحسابات المالية** | Integer Halalas Ledger Engine | معالجة مبالغ وفروق التسوية بوحدة الهللة الصحيحة (1 ر.س = 100 هللة) |
| **منظومة الاختبارات** | Node Test Runner (`node:test`) + Playwright | اختبارات وحدة برمجية للمنطق الخالص واختبارات بصرية للمتصفح (حاسوب وهاتف) |

## 5. تفاصيل السيناريوهات التشغيلية الخمسة (Scenarios Specification)

### الحالة 1 (S1) — مطالبة عيادة مكتملة الأركان (Clean Claim)
- **المعرف والمبلغ:** `CLM-S1-300` بمبلغ 300 ريال سعودي.
- **الخدمة والتشخيص:** `DEMO-SVC-01` (استشارة عيادات خارجية) + `DEMO-DX-01` (التهاب بلعوم حاد).
- **مسار القواعد:** اجتياز كامل وتوجيه فوري للمراجعة البشرية دون استهلاك ذكاء اصطناعي.
- **القرار البشري:** اعتماد المطالبة وتصديرها إلى محاكي التأمين.
- **التسوية:** صدور `ClaimResponse` بالموافقة الكاملة وتسوية بنكية بمبلغ 300 ريال.

### الحالة 2 (S2) — رقم عضوية تأميني مفقود (Missing Policy Member ID)
- **المعرف والمبلغ:** `CLM-S2-300` بمبلغ 300 ريال سعودي.
- **الخلل المرصود:** حقل رقم العضوية التأمينية `memberId` فارغ في سجل التغطية.
- **مسار القواعد:** حجب حتمي عبر القاعدة `DEMO-REQ-001` وتوجيه المسار إلى `needs-correction` دون استهلاك AI.
- **التصحيح التفاعلي:** يقوم المستخدم بإدخال رقم اصطناعي (`SYN-MEM-8842`)؛ يتم إنشاء إصدار جديد `v2` وتحديث المورد في `Medplum` وإعادة فحص القواعد بنجاح حتى التصدير.

### الحالة 3 (S3) — تعارض التوثيق السريري مع الإجراء المفوتر (Documentation Mismatch)
- **المعرف والمبلغ:** `CLM-S3-600` بمبلغ 600 ريال سعودي.
- **الخدمة المفوترة:** `DEMO-SVC-02` (إجراء جراحي صغرى / تنظير تشخيصي).
- **الدليل السريري (`DOC-S3-1`):** يتضمن النص الحرفي الموثق:  
  *«حضر المراجع للاستشارة ولم ينفذ الإجراء في هذه الزيارة نظراً لرغبة المريض بتأجيل التدخل للأسبوع القادم»*.
- **تدخل الذكاء الاصطناعي:** تظليل النص الحرفي بدقة، واقتراح تعديل الخدمة إلى استشارة موثقة (`DEMO-SVC-01`) بقيمة 200 ريال أو رفض المطالبة.
- **القرار البشري:** المراجع يختار الاعتماد كاستشارة موثقة بـ 200 ريال؛ ينشأ الإصدار `v2` ويعتمد بنجاح.

### الحالة 4 (S4) — رفض لغياب مرفق متوفر ومبادرة «نتعلّم معاً» (Denial & Learn Together)
- **المعرف والمبلغ:** `CLM-S4-1000` بمبلغ 1000 ريال سعودي.
- **الرفض التاريخي:** رمز `DENIAL-NO-ATTACHMENT` لغياب التقرير التشخيصي.
- **الحل:** التقرير `DOC-S4-1` متوفر في أرشيف المريض؛ ينقر المراجع لإرفاقه بالحزمة، ويولد النظام مسودة اعتراض رسمية تستند للعقد التجريبي.
- **مبادرة «نتعلّم معاً»:** اقتراح تفعيل القاعدة `DEMO-REQ-004` لمنع إرسال `DEMO-SVC-03` دون مرفق؛ يتم تنفيذ 3 اختبارات قبول آلية قبل تفعيلها للجلسة.

### الحالة 5 (S5) — دفتر التسوية ومطابقة الفروق البنكية (Financial Reconciliation)
- **المعرف والمبلغ الإجمالي:** `CLM-S5-2000` بمبلغ 2000 ريال سعودي.
- **دفتر الحسابات المفصل (بالهللات والريال):**
  1. إجمالي الفاتورة: 200,000 هللة (2000 ر.س).
  2. الخصم التعاقدي للشبكة (10%): 20,000 هللة (200 ر.س).
  3. المبلغ المسموح به: 180,000 هللة (1800 ر.س).
  4. تحمل المريض (محصل نقداً): 20,000 هللة (200 ر.س).
  5. صافي المستحق من التأمين: 160,000 هللة (1600 ر.س).
  6. إشعار السداد الأولي (`REMIT-S5-01`): 140,000 هللة (1400 ر.س).
  7. فرق التأمين المتبقي: 20,000 هللة (200 ر.س) قيد التحقيق.
- **الإجراء:** منع إغلاق الملف حتى استلام الدفعة التكميلية (`REMIT-S5-02`) بمبلغ 200 ر.س والمطابقة البنكية المستقلة.

## 6. مصفوفة تسليم المكونات الفنية والامتثال (Compliance Matrix)

| المكون الفني | حالة التنفيذ في المحاكي | التفاصيل والملاحظات |
|---|---|---|
| **مستودع FHIR Core** | ✅ **مستخدم فعلياً (`@medplum/mock`)** | بناء حقيقي على `MockClient` و`MemoryRepository` لتخزين موارد `Patient`, `Claim`, `Task`, `DocumentReference`, `ClaimResponse`, `PaymentReconciliation`. |
| **محرك القواعد** | ✅ **`typesafe/jev-1.13` حياً + بديل TypeScript** | في الوضع الحي يعمل عبر نموذج القرارات `typesafe/jev-1.13` بـ OpenRouter، مع بديل TypeScript محلي وموسوم في الوضع الثابت. |
| **الذكاء الاصطناعي** | ✅ **OpenRouter حصرياً (Zero Google API)** | يعتمد على `qwen/qwen-2.5-72b-instruct` للاستدلال السريري والتصنيف، مع وضع ثابت مسبق الصنع للمحاكاة دون مفاتيح. |
| **حفظ وتخزين البيانات** | ✅ **ذاكرة الجلسة الحية (In-Memory)** | تخزين مؤقت داخل ذاكرة المتصفح مع ميزة تصدير واستيراد لقطة كاملة بصيغة JSON. |
| **المحاكيات الخارجية** | ✅ **محاكيات اصطناعية مدمجة** | محاكي لنظام المستشفى (HIS)، ومحاكي لشركة التأمين ومطالبات نفيس، ومحاكي للبنك والمطابقة المصرفية بدقة الهللات. |
| **التصميم والواجهة** | ✅ **متجاوب 100% باللغة العربية (RTL)** | مبني بـ React 19 + Tailwind CSS v4، خط Cairo العربي، وعزل تام للمعرفات والأكواد بالاتجاه LTR. |

## 7. أبعاد القيمة الستة (3C + 3P ≡ V)

يقيس المحاكي الأثر التشغيلي والمالي عبر ستة أبعاد متوازنة ومترابطة:

- **C1 - الرعاية وتغطية الأدلة (Care):** نسبة الملاحظات المستندة لنص سريري حرفي موثق ومطابق.
- **C2 - تكلفة الذكاء الاصطناعي (Cost):** إجمالي التكلفة المقاسة للاستدعاءات المادية للنماذج التوليدية ونموذج القرارات.
- **C3 - اجتياز الفحص الأول (Claims):** نسبة المطالبات النظيفة التي اجتازت قواعد الأعمال من أول محاولة.
- **P1 - المدفوعات والتسوية (Payments):** مبالغ المطالبات المسواة بنكياً وتتبع الفروق المعلقة.
- **P2 - اكتمال التشغيلات (Performance):** نسبة المسارات التي وصلت لحالتها النهائية المحددة.
- **P3 - الإنتاجية وسرعة المراجعة (Productivity):** متوسط زمن قرار المراجع البشري ونسبة تعديل المقترحات.

> **ملاحظة إحصائية:** يتم التعامل مع المقامات الصفرية بعرض عبارة **«لا بيانات»** تجنباً لأي تشويه أو تضليل رقمي.

## 8. إعداد وتشغيل المشروع (Setup & Run)

### المتطلبات الأساسية
- Node.js 20+ أو Node.js 22
- مدير الحزم `npm`

### 1. تثبيت الاعتماديات
```bash
npm install
```

### 2. إعداد المتغيرات البيئية (`.env`)
أنشئ ملف `.env` بناءً على النموذج:
```bash
# مفتاح OpenRouter (المزود الحصري للوضع الحي)
OPENROUTER_API_KEY="sk-or-v1-..."

# نماذج OpenRouter المعتمدة
AI_RULES_MODEL="typesafe/jev-1.13"
AI_CLASSIFIER_MODEL="qwen/qwen-2.5-72b-instruct"
AI_REASONER_MODEL="qwen/qwen-2.5-72b-instruct"

# رابط التطبيق
APP_URL="http://localhost:3000"
```

### 3. تشغيل خادم التطوير (Full-Stack)
```bash
npm run dev
```
افتح المتصفح على: `http://localhost:3000`

### 4. البناء للإنتاج (Production Build)
```bash
npm run build
npm start
```
