# أجا | محاكي دورة الإيرادات وذكاء القيمة (AJA RCM Simulator)
**الإصدار 2.0 — النسخة الموحدة**

تطبيق ويب عربي تفاعلي متقدم يحاكي دورة الإيرادات الصحية (Healthcare Revenue Cycle Management - RCM) وفق معايير FHIR وقواعد الأعمال الحتمية، مع بوابة ذكاء اصطناعي آمنة ومراجعة بشرية في الحلقة (Human in the Loop).

---

## 📋 مصفوفة تسليم المكونات الفنية (Compliance Matrix - القسم 17)

| المكون الفني | حالة التنفيذ في المحاكي | التفاصيل والملاحظات |
|---|---|---|
| **مستودع FHIR Core** | ✅ **مستخدم فعلياً (`@medplum/mock`)** | بناء حقيقي على `MockClient` في الذاكرة لتخزين `Patient`, `Claim`, `Task`, `DocumentReference`, `ClaimResponse`, `PaymentReconciliation`. |
| **محرك القواعد** | ✅ **قواعد TypeScript بديلة موسومة ومختبرة** | تنفيذ حتمي لكافة قواعد العقد التجريبي (`DEMO-REQ-001` إلى `DEMO-REQ-005`)، مع ميزة اختبار واقتراح القواعد («نتعلّم معاً»). |
| **الذكاء الاصطناعي** | ✅ **وضع ثابت مكتمل + وضع حي مهيأ عبر وسيط الخادم** | يبدأ بوضع محاكاة ثابت لا يتطلب أي مفتاح؛ ويدعم الاستدعاء الحي لنماذج `Qwen` أو `Gemini` عبر Express Server دون كشف أي أسرار في المتصفح. |
| **حفظ وتخزين البيانات** | ✅ **ذاكرة الجلسة الحية (In-Memory)** | تخزين مؤقت خفيف داخل ذاكرة المتصفح عبر `MemoryRepository` مع خيار تصدير واستيراد لقطة كاملة بصيغة JSON. |
| **المحاكيات الخارجية** | ✅ **محاكيات اصطناعية مدمجة** | محاكي لنظام المستشفى (HIS)، ومحاكي لشركة التأمين ومطالبات نفيس، ومحاكي للبنك والمطابقة المصرفية بدقة الهللات. |
| **التصميم والواجهة** | ✅ **متجاوب 100% باللغة العربية (RTL)** | مبني بـ React 19 + Tailwind CSS v4، خط Cairo العربي، وعزل تام للمعرفات والأكواد بالاتجاه LTR. |

## 🎯 الحالات الخمس المعتمدة (القسم 11)

1. **الحالة 1 (S1) — مطالبة مكتملة الأركان (300 ر.س):**
   - فحص القواعد الحتمية ناجح دون استدعاء الذكاء الاصطناعي.
   - جاهزة للمراجعة البشرية، تليها الموافقة والتسوية البنكية الكاملة (300 ر.س).
2. **الحالة 2 (S2) — رقم عضوية تأميني ناقص:**
   - حجب حتمي عبر القاعدة `DEMO-REQ-001` وتوقف فوري للمسار دون استهلاك AI.
   - إمكانية إدخال رقم العضوية المفقود من قبل المراجع، وإنشاء إصدار جديد v2، وإعادة فحص القواعد حتى الاعتماد.
3. **الحالة 3 (S3) — تعارض التوثيق السريري مع الإجراء المفوتر (600 ر.س):**
   - فوترة خدمة إجراء جراحي صغرى (`DEMO-SVC-02`) بينما توثق الملاحظة السريرية صراحة أن الإجراء لم ينفذ بل استشارة فقط.
   - استدلال الذكاء الاصطناعي مع تظليل النص الحرفي المقتبس (`DOC-S3-1`).
   - عرض مقارن بين الخدمة الحالية والتصحيح المقترح (200 ر.س) مع خيار الاعتماد أو الرفض.
4. **الحالة 4 (S4) — رفض مطالبة لغياب مرفق متوفر بالملف (1000 ر.س):**
   - رفض أولي من المؤمّن لغياب التقرير. التقرير متوفر في أرشيف المريض وسقط من حزمة الإرسال.
   - إرفاق التقرير التشخيصي المعتمد وتوليد مسودة اعتراض رسمية تستند للعقد.
   - إطلاق مبادرة **«نتعلّم معاً»**: اقتراح تفعيل القاعدة الاحترازية `DEMO-REQ-004` مع تشغيل 3 اختبارات قبول إلزامية قبل اعتمادها للجلسة.
5. **الحالة 5 (S5) — دفتر التسوية وفروق المدفوعات التأمينية:**
   - الحساب الرياضي الدقيق بالهللات:
     - إجمالي الفاتورة: 2000 ر.س
     - الخصم التعاقدي للشبكة: 200 ر.س
     - المبلغ المسموح به: 1800 ر.س
     - تحمل المريض (محصل نقداً): 200 ر.س
     - صافي المستحق من التأمين: 1600 ر.س
     - إشعار السداد الأولي (REMIT-S5-01): 1400 ر.س
     - فرق التأمين المتبقي: 200 ر.س
   - قفل الإغلاق المالي وفتح مهمة متابعة، ثم استلام دفعة تكميلية بمطابقة بنكية مستقلة.

## 📊 أبعاد القيمة الستة (3C + 3P ≡ V)

- **C1 - الرعاية وتغطية الأدلة (Care):** نسبة الملاحظات المستندة لنص سريري حرفي موثق ومطابق.
- **C2 - تكلفة الذكاء الاصطناعي (Cost):** إجمالي التكلفة المقاسة للاستدعاءات المادية للنماذج التوليدية.
- **C3 - اجتياز الفحص الأول (Claims):** نسبة المطالبات النظيفة التي اجتازت قواعد الأعمال من أول محاولة.
- **P1 - المدفوعات والتسوية (Payments):** مبالغ المطالبات المسواة بنكياً وتتبع الفروق المعلقة.
- **P2 - اكتمال التشغيلات (Performance):** نسبة المسارات التي وصلت لحالتها النهائية المحددة.
- **P3 - الإنتاجية وسرعة المراجعة (Productivity):** متوسط زمن قرار المراجع البشري ونسبة تعديل المقترحات.
*(المقام صفر يعرض «لا بيانات» منعاً للتضليل الإحصائي).*

## 🛠️ المعمارية والتقنيات المستخدمة

- **الواجهة:** React 19, TypeScript, Tailwind CSS v4, Lucide Icons, Motion.
- **إدارة الموارد السريرية:** `@medplum/mock` v2026.10, `@medplum/core`.
- **الخادم والوسيط:** Express, Vite Middlewares (`server.ts`).
- **حماية البيانات:** وحدة «تقليل البيانات قبل AI — تجربة توضيحية» لاستبدال المعرفات بالرموز وتنقيح الحقول الإدارية.
- **الأسرار والبيئة:**
  - `OPENROUTER_API_KEY`: مفتاح اختياري لاستدعاء نماذج OpenRouter (مثل Qwen 2.5).
  - `AI_CLASSIFIER_MODEL`: اسم نموذج التصنيف في الظل (افتراضي: `qwen/qwen-2.5-72b-instruct`).
  - `AI_REASONER_MODEL`: اسم نموذج الاستدلال والأدلة (افتراضي: `qwen/qwen-2.5-72b-instruct`).
  - `GEMINI_API_KEY`: مفتاح بديل متاح تلقائياً عبر منصة AI Studio.

## 🧪 الاختبارات الآلية المنفذة

تم فحص التطبيق بنجاح عبر اختبارات الوحدة واختبارات المتصفح الحقيقية:
- `npm run test`: اختبارات المنطق الحسابي لدفتر التسوية S5، معالجة المقامات الصفرية للمؤشرات، ومطابقة الاقتباسات السريرية.
- `npx tsx --test src/adapters/rules/rules.test.ts`: اختبارات قواعد الأعمال والحالات الخمس والاختبارات الثلاثة لمبادرة «نتعلّم معاً».
- `playwright-cli`: فحص تفاعلي ومصري للشاشات والأزرار واختصارات لوحة المفاتيح (`Ctrl+Enter`)، وتجاوب الشاشات على مقاسي الحاسوب (1440x900) والهاتف (390x844).
